vibecms has no passwords. On the sign-in page, enter your email and choose **Email me a code**. The email carries a 6-digit code that stays valid for 10 minutes; enter it to land in your dashboard. Asking for another code works, but requests are rate-limited — wait for the cool-down shown on screen.

If the deployment has Google or GitHub credentials configured, the same page shows **Continue with Google** or **Continue with GitHub**. These buttons appear only when the providers are set up; email codes are the default method on hosted vibecms. Self-hosted installs need a configured email binding and onboarded sender domain for real delivery — see [self-hosting](/docs/self-hosting). The first sign-in creates your blog and its workspace, so signing in for the first time *is* signing up.

If you started an agent connection first, sign in and you will return to the approval screen. Choose a blog you own and an access level before allowing the app.

## Roles

Each person on a blog has a role: **owner** or **editor**.

Editors do the writing work: read the site, create and edit posts, publish, schedule, archive and restore, upload and delete images, and read activity. Only the owner can:

- Connect and disconnect apps, and create and revoke agent keys (**Dashboard > Connect**)
- Change site, voice, and theme settings, and connect a domain or subpath location (**Settings**)
- Upgrade, manage, or cancel the subscription (**Settings > Plan & billing**)
- Export posts and the subscriber CSV

Owners and editors can permanently delete archived posts; agents never can. For what a connection or agent key can do, see [key levels and scopes](/docs/agent-workflows/scopes-and-tools).
