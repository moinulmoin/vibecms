# Changelog

All notable changes to VibeCMS will be documented in this file.

## Unreleased

- Theme presets v2 (plan 018): owner structural layouts plus bounded per-post layout intent. Posts gain a typed `presentation` field - `{ layout: 'standard' | 'feature' | 'essay'; toc?: boolean }` or `null` to follow the active preset default - that agents and humans SELECT (never inject structure): it flows through `posts.create`/`posts.update` (MCP + REST) and the dashboard editor, persists on `posts` and `post_versions` (so version restore is faithful), and is interpreted by the owner's theme preset. Each preset declares its supported layouts, default, and whether it offers a table of contents (`ThemePreset.layout`); `resolvePresentation` clamps unsupported requests to the preset default and returns warnings, so a post never breaks when the site switches presets and the agent sees exactly what it gets. ONE shared `PresentedPostArticle` renders the public post page, `posts.preview`, and the editor preview from a single parse (preview == public == editor): a `data-vc-layout` attribute drives the structural CSS - essay gets a narrower measure plus a drop cap, feature gets a full-width cover hero, plus an optional page-level table-of-contents block (not a sidebar in v1). `posts.preview` now returns the requested and resolved presentation plus warnings, and `posts.format_guide` advertises each preset's allowed `presentationOptions` (preferring the typed `presentation.toc` over an inline `[[toc]]`). Markdown export serializes non-null presentation under a generated `vibecms:` front-matter key (never parsed back from authored content). Migration `0010` adds the nullable `presentation_json` column; the preset/`Presentation` types are platform-neutral (Workers runtime env moved to a `@vc/config/runtime` subpath). Verified end-to-end on dev (agent create persists presentation; preview clamps and surfaces; essay drop cap and feature hero render). Out of scope in v1: independent width/hero knobs, hero split, sticky sidebar TOC, product CTA emphasis, and site-level defaults.
- Theme presets, per-preset agent guidance, and first-party audience capture (plan 015). Owners pick one of four curated presets (Minimal default, Editorial, Technical, Product) in a new Public blog settings panel - with an illustrative live preview and a Light/Dark/System preview toggle - and the choice persists to a re-added `sites.theme` column. A preset is a `--vc-*` design-token skin over the ONE semantic DOM the shared renderer emits (no content fork): the WHOLE public page - header, article body, and capture widget - reskins coherently in light and dark (system `prefers-color-scheme`), driven by `data-vc-theme` on the page root, with `@tailwindcss/typography` prose bridged from the tokens so each preset carries its own fonts, measure, and density. The agent `posts.format_guide` tool now returns the active preset's tonal authoring guidance (versioned; recommendation, not syntax - every recommended component maps to a real renderer component), and `posts.preview` renders at the site's active preset by default (explicit `presetId` overrides), so preview == public == editor. A first-party email capture widget (end-of-post and footer) stores `pending` signups in a new `subscribers` table with the exact consent text/version, double-opt-in modeled for a later send: honest early-list copy that never implies a confirmed subscription, a honeypot, per-site rate limiting keyed by canonical id, body-size caps, HMAC-hashed IP/UA, and idempotent no-enumeration responses. NO email is sent yet (that is plan 017). The preset registry lives in `@vc/config`. Verified end-to-end on dev: preset-aware format_guide and preview, the full subscribe matrix, and coherent light/dark theming across presets (browser-checked).
- Rich content rendering plus an agent fidelity loop (plan 016). The public blog, the dashboard editor preview, and a new agent preview now share ONE Markdown renderer - a `unified` remark/rehype pipeline ending in `rehype-react` with `rehype-sanitize`, replacing the hand-rolled single-pass parser - so what an agent previews is exactly what publishes. v1 adds GitHub-style callouts (`> [!NOTE]`/`[!TIP]`/`[!IMPORTANT]`/`[!WARNING]`/`[!CAUTION]`), an explicit `[[toc]]` table of contents (H2/H3), captioned images (an image line immediately followed by a single emphasis-only line becomes a `<figure>`), and language-labelled code blocks, all skinned by a new `--vc-*` CSS design-token system on `[data-rich-content]` (light now; dark values staged for the plan-015 theme presets). Two new read-only tools teach and verify the format: `posts.format_guide` (MCP tool + `GET /api/v1/posts/format-guide`) returns the supported syntax and active-preset guidance with a `guideVersion`/`rendererVersion`, and `posts.preview` (MCP tool + `POST /api/v1/posts/preview`) renders Markdown with the same renderer and returns `{ html, outline, warnings, rendererVersion }` so an agent can self-check before publishing (non-fatal warnings flag unknown callout types, missing image alt, a `[[toc]]` with no headings, and code fences missing a language). The connect onboarding prompt now teaches the loop fetch guide -> draft -> preview -> publish, and a root `SKILL.md` ships the same vocabulary for coding agents. XSS-safe by construction: raw HTML never becomes elements (`allowDangerousHtml: false`, no `rehype-raw`), sanitization runs last, and `javascript:` URLs are stripped; heading ids are `h-`-prefixed so TOC anchors resolve without DOM-clobbering risk. Covered by the repo's first automated tests (vitest: render parity, XSS regression, validator warnings) and verified end-to-end on dev (preview, format_guide, and public render).
- Post version history is now readable and restorable. Every create/edit/publish already snapshots the post into `post_versions`, but no surface could read or restore them; added `posts.versions.list/get/restore` MCP tools, REST routes (`GET /api/v1/posts/:id/versions`, `GET .../versions/:n`, `POST .../versions/:n/restore`), and a Version History drawer in the post editor (view a past version read-only, restore behind a confirm). Restore is content-only and never re-publishes (status and `published_at` are untouched); it writes a fresh version plus a `post.restored` activity event, is site-scoped at the SQL level, and reuses the existing atomic version/concurrency contract. Verified end-to-end on dev.
- Migrated the web app from RedwoodSDK to TanStack Start (on the Cloudflare Vite plugin) so it runs on the Workers **Free** plan: public and blog pages are SSR with edge cache plus per-article tag purge, the dashboard is a client SPA over auth-gated server functions, and the agent API stays cheap JSON. `dev.vibecms.dev` is cut over to the new app; a concurrent fresh-request burst that returned 503 (Error 1102) on RedwoodSDK now returns 200. The shared `@vc/*` packages (core, db, validators, mcp, config, ui) are unchanged.
- Closed a CSRF gap introduced by the TanStack migration: dashboard mutations moved to `createServerFn` POSTs (`/_serverFn/*`), which TanStack serves with no Origin check and which a cross-origin HTML form can reach, leaving the cookie-authed mutation surface (mint a full-scope agent token, change site settings, write posts) open to request forgery. Registered the framework's `createCsrfMiddleware` as global request middleware (`src/start.ts`) scoped to server functions, so Bearer/HMAC agent routes (MCP, REST, Polar webhook) stay open, and added the same Origin guard to the cookie-authed `/api/media/upload` route. Cross-origin and origin-less mutating requests now return `403`; same-origin dashboard calls are unaffected.
- One public API over the same `@vc/core`, for agents and humans: a versioned REST surface at `/api/v1` (Hono + `@hono/zod-openapi` mounted in the worker) covering the full post lifecycle (list/get/create/update/publish/archive), site, activity, and asset upload, with a committed OpenAPI 3.1 spec served at `/api/v1/openapi.json`, interactive Scalar docs at `/api/v1/docs`, and a CI drift gate so the spec can never fall behind the code. The existing MCP tools now also return structured output (`outputSchema` + `structuredContent`, keeping the text-JSON fallback) and behavior annotations (`readOnlyHint`/`destructiveHint`/`idempotentHint`) so agents get typed, parseable results with per-route error responses. A new pure `@vc/api-contract` package (request/response schemas, scopes, error envelope, DTO mappers) and a shared operation layer are the single source REST and MCP both route through, so the two cannot drift; the bearer auth, scopes, quotas, and tenant isolation are reused unchanged. Ships `@vibecms/cli`, a zero-dependency, agent-ergonomic command-line client (`--json`/`--ndjson`, `--dry-run`, stable exit codes, `VIBECMS_*` env with flag>env>config precedence, and a `schema` command that dumps the API for agent introspection), with a changesets pipeline to publish it to npm.
- Full dark dev-tool visual redesign of the landing page and dashboard. The marketing landing is a new dark, terminal-flavored design (Space Grotesk display + Hanken Grotesk body + JetBrains Mono labels, all self-hosted; bright-green accent, dot-grid texture, glass and panel surfaces, editor/terminal mockups, scroll-reveal and the live scope-toggle demo). The design tokens were retuned to the new palette in oklch: the landing renders dark always, while the dashboard, auth, and onboarding carry the same language across both light and dark. Borders and inputs meet WCAG non-text contrast in both modes. No behavior, route, or form changes - visual only.
- Passwordless sign-in: replaced email + password with a 6-digit email OTP (the account is created and the email verified on the first valid code, so impersonation via an unowned address is no longer possible), plus an optional "Continue with Google" button that appears only when Google OAuth credentials are configured. Codes are emailed via Plunk in production (`PLUNK_API_KEY`/`EMAIL_FROM` on a Plunk-verified sender domain) and logged to the Worker console when unset for local testing. No schema change - reuses Better Auth's existing `verification` and `account` tables.
- OTP send abuse guard: each recipient email is capped at 5 codes/hour in durable D1 storage (a dedicated `rate_limits` table, atomic conditional `UPDATE` so concurrent sends cannot overshoot), keyed on the recipient - not source IP, which rotates and would punish shared networks. Only requests Better Auth would actually accept count against the cap (gated on JSON content type and a plausible address), so a rejected request cannot lock a victim out, and the limiter fails open if storage is unavailable.
- Draft-free, publish-one-free hosted model: signing up, naming a blog, drafting/editing posts, creating agent tokens, and connecting agents over MCP are free. Each workspace can publish ONE post free to try the full loop end to end - it renders live but `noindex,nofollow` - and a subscription is required to publish more, upload media, and make posts search-indexable. Enforced for both the dashboard and the agent (MCP) path; unpaid usage is bounded by a new free API tier; self-host stays fully free.
- Hardened the publish-one-free path after review: the free-publish cap is now enforced atomically in the DB write (a conditional `UPDATE` whose count check D1 serializes), closing a concurrent-publish race; and unpaid blogs are kept out of discovery - no sitemap entry, and `noindex,nofollow` plus `content-signal: search=no` on their feed, `llms.txt`, and markdown responses (the HTML page was already `noindex`).
- Agent-first onboarding rework (`/app/connect`): after blog setup you mint a non-destructive publish token and then watch your own agent connect and publish your first post over MCP. A server-side status (`loadOnboardingStatus`) is polled to detect the agent authenticating (the token's `last_used_at` advancing past creation) and the first `post.published`, then the step reveals the live public URL with honest framing (the post is live but `noindex` until you subscribe) and the upgrade CTA, with all prices derived from the central `PRICING` config. The starter prompt now creates AND publishes the first post (it previously left a draft); `/app/setup` can optionally prefill blog name/slug/description from an existing website URL (client-side only, never scraped or imported); the freshly minted token still appears inline in every client snippet; and the agent step stays skippable with a "write your first post manually" fallback. The single free publish is the activation moment, and an already-published blog skips straight to the live reveal instead of asking for a second publish.
- Agent token presets are now Publisher (the default: read, create, update, publish, and media uploads, but NOT archive) and Full (adds archiving), replacing the prior draft-only default so a connected agent can publish without a separate opt-in; archiving stays gated to Full. App-minted tokens now carry the `vc_live_` prefix (the prior `vc_test_` is reserved for the `pnpm dev:token` dev helper); the prefix is cosmetic since tokens are matched by hash, so no migration is needed.
- Cohesive design system: token-driven light + dark themes (oklch, single green accent), Geist/Geist Mono, motion + radius tokens. Removed unused Instrument Serif.
- Marketing site rebuilt on tokens with honest dev-tool visuals (MCP write and REST read samples), canonical copy, accessible structure, and no fabricated screenshots.
- Dashboard redesigned on a shared `AppFrame`/`DashboardShell`/`OnboardingFrame` with Radix icons, mobile nav, skip link, and consistent spacing.
- Inline success/error feedback for every form via post-redirect status codes; pending and destructive-confirm states; copy-to-clipboard for the one-time API token.
- One-time API token reveal hardened with a short-lived HttpOnly cookie handoff cleared server-side.
- Public blog markdown renderer expanded (links, lists, code, blockquotes) with safe-href scheme allowlisting and per-post SEO metadata.
- Centralized brand, pricing, media, and entitlement copy in `@vc/config`; removed the unused `PLAN` constant and a duplicate `dependencies` block in `@vc/ui`.
- Replaced the uncustomized RedwoodSDK starter page.
- Workspace-level API quotas shared by MCP and REST (per-minute/day/month calls, daily/monthly writes, plus a per-token burst cap); over-limit requests return `429` with machine-readable `RATE_LIMIT` (REST) and a JSON-RPC rate-limit error (MCP). Self-hosted mode is exempt. Dashboard shows live usage meters.
- API tokens capped per workspace (10 active) as a leak/abuse guard; over-limit creation returns a clear "token limit reached" message.
- Fixed yearly checkout silently charging the monthly product when no yearly product is configured; yearly now requires its own product or returns a clear "yearly unavailable" message.
- Launch smoke suite extended to cover the REST/MCP happy path and the quota-denial (`429`) path.
- MCP `initialize` now returns server `instructions` so a connecting agent learns the draft->publish flow (no scheduling), post format and limits, image upload, and rate-limit handling without trial and error; tool descriptions sharpened to reinforce the workflow.
- MCP transport conformance: negotiate protocol version (advertise `2025-06-18`, echo a supported requested version, reject an unsupported `MCP-Protocol-Version` header), `GET /mcp` returns `405`, and custom tool metadata moved under `_meta` instead of non-standard top-level Tool keys. Recoverable tool errors (invalid input, duplicate slug, not found) now return as `CallToolResult{isError:true}` so agents self-correct, while auth/billing/rate-limit/protocol errors stay JSON-RPC. MCP `assets.upload` now records the real workspace and maps upload failures to clear messages.
- Removed the hosted free trial. Hosted billing is now subscribe-to-publish only (a single 5 GB media tier, no trial storage cap); self-host stays free and fully unblocked. Dropped the `trialing` status, trial quota tier, trial-expiry handling, and all trial copy/CTAs; public blogs are indexable once active (or self-hosted). Migration `0006_remove_trial.sql` normalizes any legacy trialing rows.
- Post editor now auto-derives the slug from the title for new posts, without overwriting a manually edited slug.
- Dashboard splits the conflated tokens/versions stat into distinct "Active tokens" and "Saved versions" cards.
- Agent-ready by default: every public blog serves `llms.txt` (content index linking to clean markdown) and per-post markdown via `Accept: text/markdown`, a `.md` suffix, or `?format=md` - the post's own source, zero-loss, with YAML frontmatter - on both custom-domain and `/blog/:siteSlug` paths. The product host also serves a `llms.txt`, `sitemap.xml`, and a sitemap-referencing `robots.txt`. Combined with the MCP endpoint, this covers the standard AI Agent Readiness checks (robots, sitemap, llms.txt, markdown, MCP).
- Fixed a data-loss bug where a partial `posts.update` (e.g. changing only the excerpt or title via MCP/REST) wiped the post body and tags: the shared zod schema's `.default("")`/`.default([])` survived `.partial()`, so omitted fields parsed to empty values instead of `undefined`. `updatePostInput` is now a true patch (all fields optional, no defaults); unspecified fields are preserved. Create-time defaults are unchanged.
- Checkout failures now surface a distinct `checkout_failed` status (and log the underlying Polar error) instead of the misleading `polar_unconfigured`, which implied missing secrets when the real cause was elsewhere (e.g. a customer email Polar rejects).
