# Changelog

All notable changes to vibecms will be documented in this file.

## Unreleased

- Polar webhook verification accepts both legacy full-string HMAC keys and Standard Webhooks keys issued after 8 September 2026, preserving SDK payload validation and existing billing receipt/order behavior. Added a sandbox-first signing-secret rotation and recovery runbook.
- SEO & GEO check (plan 028): `posts.preview` and `posts.seo_check` gain five deterministic AI-answer rules on every plan: `answer-intro-missing` (warn: the post opens with a heading, list, or quote instead of a paragraph), `answer-intro-long` (opening paragraph over 80 words), `answer-claim-unsourced` (a percentage, multiplier, or millions-scale number with no link in its paragraph), `answer-section-long` (over 400 words under one heading), and `answer-steps-prose` (steps written as prose). 31 rules in total. A new `vibecms-seo` skill gives the customer's own agent the judgment questions to answer with its own model, and `vibecms-core` now fixes `error` and `warn` findings before asking for approval.
- Removed the Workers AI SEO review: `posts.seo_check` and `GET /api/v1/posts/{postId}/seo` no longer accept `ai` and no longer return `ai` or `warnings`, the `AI_UNAVAILABLE` error code is gone, the editor's "Ask AI review" button is gone, the API Worker drops its `AI` binding and `SEO_REVIEW_MODEL`, and migration 0042 drops the `post_seo_reviews` cache table. vibecms runs no AI model on customer content; the privacy policy says so.
- Free hosted blogs show a small "Published with vibecms" link to vibecms.dev in the page footer, in the blog's own theme colors. Paid blogs (Polar or AutoSEOPilot sponsorship) and self-hosted installs never show it.
- vibecms Cloud has no monthly cap on agent calls or writes anymore. The per-minute, per-day and per-key guardrails stay; this month's totals are still counted for the dashboard. The free plan's monthly caps are unchanged.
- Paid media storage is 10 GB, up from 5 GB.
- The claim-window sweep now runs on the 15-minute cron instead of the daily one and stays inside an explicit D1 query budget of 500 per run (D1 allows 1,000 per invocation): every query it makes is counted, a reminder or purge only starts when the budget still covers its worst case, and the rest waits for the next run.
- Claim reminders belong to one claim window: a revoke after a resumed AutoSEOPilot plan clears the four reminder markers in the same guarded write, and a reminder is only marked for the window (revoke time and lifecycle revision) the sweep read, so a new window gets all its reminders and an older sweep can never mark a newer window.
- A late Polar event for a blog that is being (or was) purged is still recorded, but the "refund needed" notice only goes out when the event proves a successful payment (an active subscription or a succeeded checkout; migration 0041 adds `payment_evidence`). Unpaid, incomplete or cancelled events no longer ask for a refund, on the normal path and the deleted-workspace fallback.
- A paused blog's feed, sitemap, `llms.txt` and share cards now answer the "This blog is paused" response (503, `noindex`, `no-store`) like every other ingress, instead of a bare 404.
- The dashboard billing payload carries the blog's serving state separately from the claim window. A blog that was claimed and later lost its vibecms Cloud subscription is no longer told "Posts stay online" while visitors see the paused page: the billing page and the banner say it is paused (or when it pauses) and that subscribing again brings it back, with no deletion date.
- The claim-window purge is now a durable three-step operation instead of a best-effort delete: a blog past its 30-day deadline first gets a purge intent (one atomic write that only lands while the blog is still revoked, still past its own deadline, still never claimed, and that records the Cloudflare hostname ids and R2 prefixes the purge will delete), the external cleanup runs from that intent, and only then are the D1 rows deleted. While the intent exists the blog cannot come back: the claim checkout is refused before any money is taken, an in-flight billing webhook is answered with a conflict instead of reviving the blog, the AutoSEOPilot plan resumption is refused with a retryable failure, a re-provision cannot recreate the same site, and a crashed purge is resumed by the next daily run.

- Dashboard launch fixes: restore AA secondary/error text contrast, validate permanent blog addresses inline with race-safe taken-address feedback, and add onboarding sign-out.
- Clipboard controls no longer claim success after failed copies; manual-copy recovery preserves multiline values. Shared segmented controls now support radio arrow-key navigation.
- Restore dialog, mobile navigation, OTP and key-creation focus; protect unsaved media alt text; rebase subscriber-form revisions on discard.
- Overlay dismissal preserves focus already moved to a destination page. Re-activating selected theme layout and editor view segments keeps their preview/panel actions without duplicating selection changes.
- Correct overview progress and one-time-key persistence copy, use inline site-name validation, remove theme-preview key/nesting warnings, label archived-post actions Unarchive, and offer retry when analytics data is unavailable.

The daily rollup keeps 365 days of detail then monthly all-time aggregates; legacy crawler rows only fill dates without agent data.
- SEO checks (plan 024): `posts.preview` and `posts.seo_check` / `GET /api/v1/posts/{postId}/seo` return deterministic findings, with an opt-in Workers AI review cached per post version and model (3/day free, 100/day paid, `AI_UNAVAILABLE` without a binding). The editor gains an SEO checklist and AI review section, and the publish dialog surfaces findings.
- Blog template structure: navigation, home page, and article header are now independent per-template structure choices across the four presets, which all support standard/essay/feature/wide layouts and a table of contents.
- Dashboard restyled on a Fumadocs-style shell: docs-style code blocks, one shared SegmentedControl and selected-state treatment, and a single Steps block across the first-run journey.
- Managed AutoSEOPilot provisioning now verifies the site's public URL before any entitlement reconcile, credential rotation, or reactivation commits, so a site whose default domain cannot resolve fails with `INTERNAL_ERROR` and no state change, instead of committing and then returning an error. Active receipts are now typed with a non-null `publicUrl`; revoked receipts may still return `null`. The managed location check now requires an effective entitlement and records verification.
- CI now runs checks and test groups as parallel jobs.

- Post version history is now readable and restorable. Every create/edit/publish already snapshots the post into `post_versions`, but no surface could read or restore them; added `posts.versions.list/get/restore` MCP tools, REST routes (`GET /api/v1/posts/:id/versions`, `GET .../versions/:n`, `POST .../versions/:n/restore`), and a Version History drawer in the post editor (view a past version read-only, restore behind a confirm). Restore is content-only and never re-publishes (status and `published_at` are untouched); it writes a fresh version plus a `post.restored` activity event, is site-scoped at the SQL level, and reuses the existing atomic version/concurrency contract. Verified end-to-end on dev.

The shared `@vc/*` packages (core, db, validators, mcp, config, ui) are unchanged.

Cross-origin and origin-less mutating requests now return `403`; same-origin dashboard calls are unaffected.

The existing MCP tools now also return structured output (`outputSchema` + `structuredContent`, keeping the text-JSON fallback) and behavior annotations (`readOnlyHint`/`destructiveHint`/`idempotentHint`) so agents get typed, parseable results with per-route error responses. A new pure `@vc/api-contract` package (request/response schemas, scopes, error envelope, DTO mappers) and a shared operation layer are the single source REST and MCP both route through, so the two cannot drift; the bearer auth, scopes, quotas, and tenant isolation are reused unchanged. Ships `@vibecms/cli`, a zero-dependency, agent-ergonomic command-line client (`--json`/`--ndjson`, `--dry-run`, stable exit codes, `VIBECMS_*` env with flag>env>config precedence, and a `schema` command that dumps the API for agent introspection), with a changesets pipeline to publish it to npm.

Only requests Better Auth would actually accept count against the cap (gated on JSON content type and a plausible address), so a rejected request cannot lock a victim out, and the limiter fails open if storage is unavailable.
- Draft-free, publish-one-free hosted model: signing up, naming a blog, drafting/editing posts, creating agent tokens, and connecting agents over MCP are free. Each workspace can publish ONE post free to try the full loop end to end - it renders live but `noindex,nofollow` - and a subscription is required to publish more, upload media, and make posts search-indexable. Enforced for both the dashboard and the agent (MCP) path; unpaid usage is bounded by a new free API tier; self-host stays fully free.

The starter prompt now creates AND publishes the first post (it previously left a draft); `/app/setup` can optionally prefill blog name/slug/description from an existing website URL (client-side only, never scraped or imported); the freshly minted token still appears inline in every client snippet; and the agent step stays skippable with a "write your first post manually" fallback. The single free publish is the activation moment, and an already-published blog skips straight to the live reveal instead of asking for a second publish.
