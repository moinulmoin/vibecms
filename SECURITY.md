# Security Policy

vibecms handles authentication, API tokens, billing webhooks, D1 data, and R2 media. Please report security issues privately.

## Reporting a vulnerability

Email the maintainer or open a private advisory if the repository host supports it. Do not file public issues for vulnerabilities.

Please include:

- affected version or commit
- impact and affected route/API, if known
- reproduction steps
- any logs with secrets redacted

Do not include real API keys, cookies, Polar tokens, Cloudflare tokens, `.env`, `.dev.vars`, database exports, or production user data.

## Supported versions

Until the first stable release, only the current `main` branch is supported.

## Secret handling

If a secret is accidentally committed, pasted into a public issue, or exposed in logs, rotate it immediately. This includes:

- `BETTER_AUTH_SECRET`
- `TOKEN_PEPPER`
- `POLAR_ACCESS_TOKEN`
- `POLAR_WEBHOOK_SECRET`
- Cloudflare API tokens
- API keys generated by vibecms
